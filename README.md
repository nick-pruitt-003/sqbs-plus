# SQBS Plus

Cross-platform quizbowl tournament scoring — Mac, Windows, Linux. A Tauri +
SvelteKit rewrite of [SQBS for Mac](https://github.com/nick-pruitt-003/sqbs-mac),
reading and writing the same `.sqbs` / `.qzx` files as Windows SQBS.

## Layout

| Path | What lives there |
| --- | --- |
| `src-tauri/src/sqbs_format.rs` | `.sqbs` file format — parser and writer |
| `src-tauri/src/models.rs` | Tournament data model |
| `src-tauri/src/reports.rs` | HTML report generation |
| `src-tauri/src/name_check.rs` | W-8 name-capitalization heuristic |
| `src/lib/*.svelte` | Tournament Setup, Game Entry, Reports, Settings |
| `src/lib/validation.ts` | Input parsing shared by the entry screens |
| `src/lib/bindings.ts` | Generated by tauri-specta — do not hand-edit |

## Using the format code as a library

`sqbs_format.rs` and `models.rs` are self-contained: `SqbsParser::parse` and
`write_sqbs` need only `serde` once the `specta::Type` derives are dropped.

## Tests

```bash
npm test              # Vitest — unit and component tests
cd src-tauri && cargo test --lib   # Rust — file format, reports, heuristics
```

The Rust tests cover the file format (round-trips, malformed input, the
optional trailing blocks), report generation, and the W-8 heuristic. Anything
touching `sqbs_format.rs` should come with a round-trip test.

Vitest runs under `vitest.config.js`, which is deliberately separate from
`vite.config.js` — tests compile Svelte components directly, without the
SvelteKit plugin's routing and SSR machinery. Two kinds of test live there:

- `src/lib/validation.test.ts` — pure input parsing. These also pin the
  agreement with the Rust parser: a games-played value typed in the UI and the
  same value read back from a file must come out the same.
- `src/lib/GameEntry.test.ts` — component behavior that pure functions can't
  reach, like whether an in-progress edit survives leaving the tab.

Note for component tests: Svelte removes a component's DOM *before* `onDestroy`
runs, so an unmount handler cannot flush a still-focused field. Entry state has
to be committed as it changes, not on blur.

Other checks:

```bash
npm run check   # svelte-check
npm run lint    # eslint
npm run knip    # unused files, exports, dependencies
```
